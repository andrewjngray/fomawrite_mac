# Cycle 165 part 2b: saving page edits; notes renumbered at save (notes for part 3 / cycle 166)

## API as declared
`Backend` (`src/backend.h`): `Q_INVOKABLE bool savePdf(bool force = false)`, `Q_INVOKABLE bool exportPdfPages(QUrl, QList<int> pages)` (working pages, 0-based; empty = all), properties `pdfSaveError` and `pdfSaveNotice` (both `pdfSaveErrorChanged`), `pdfRecoveryFolder()`, `failNextPdfWrite(stage)` (tests: "write", "verify", "recovery", "replace"; one use).
`PdfSession::savedToDisk()` (clears `changedOnDiskWhileEditing`, re-watches). `PdfNotes::renumber(text, fileName, QList<PageRemap>, oldLabel, newLabel)` and `PdfNotes::turnedPoint` (the one point transform; the session's drawing uses it too). New `src/pdffiles.{h,cpp}` (`PdfFiles::writeVerified`, `opens`, `recoveryCopies`), added to `fomawrite.pro` and `tests/tests.pro`.
Return values: `savePdf` is true when nothing was pending or the PDF was written; false = nothing changed, `pdfSaveError` says why. True with a non-empty `pdfSaveNotice` = PDF saved but the notes could not be renumbered or saved.

## Save sequence as built
1. Nothing pending: true. 2. Read the file; if it differs from the baseline bytes and not `force`: "The PDF changed on disk. Your page changes were not saved." (also unreadable/missing file: refused). 3. `writeVerified`: refuses read-only target; temp file `.fomawrite-XXXXXX.tmp` in the real file's folder (symlinks resolved); write, flush, fsync; read back: bytes equal and Qt PDF opens it with the expected page count; recovery copy of the on-disk bytes; permissions copied; re-read the file (must still equal what was checked); replace (POSIX `rename`, Windows `MoveFileExW` replace). Any failure: temp removed (RAII), recovery copy of this attempt removed, original untouched, session/notes untouched. 4. Success: renumber edit computed from the page map as it was, `adoptWorkingAsBaseline()`, `savedToDisk()`, edit applied through `applyNotesEdit` (one editor undo step), then `save()` of the notes if modified and (titled, or untitled with content and a save target that does not exist yet).

## Recovery copies
The existing recovery store only holds one unsaved-notes snapshot per window (`recovery-N.json`), so nothing fitted. New: `<AppData>/pdf-previous/<sha1(canonical path, lower-cased on Windows), 20 hex>/<16-digit ms timestamp>.pdf` plus `path.txt`; the latest 3 per file are kept. `PdfFiles::recoveryCopies(Backend::pdfRecoveryFolder(), path)` lists them newest first. Export also keeps the bytes of a file it overwrites. Nothing prunes folders of PDFs that no longer exist.

## Decisions (brief silent)
- Renumbering: markers `page=`, `at=` and `rect=` (turned with the page; points outside the page are left alone; `rect` is rewritten as integers), links `File.pdf#page=N` to this PDF anywhere outside code fences and inline code, plain `## Page N` headings. Link labels follow only when they read `Page <N or the old page's label>` and the page number changed; otherwise only the number changes. Identity map: empty edit.
- Removed pages: markers `page=0`; generated heading becomes `## Deleted page N`; any other heading link to it gets `#page=0` (so the parser no longer sees a section for it); links in body text to a removed page are left alone.
- Nothing is moved. `insertItem` needed no change: a mark goes into the page's existing section wherever it is; a missing section is placed before the first section with a higher page number, else after the last.
- Undo after save: the notes are not rewritten back by a page undo; saving again renumbers them back (tested, notes text returns to the original). If the writer also undoes the notes edit in the editor while a page undo is pending, marks will be drawn on wrong pages (the rebased map no longer matches the text). Items put at page=0 stay unplaced after such an undo.
- Export refuses the open PDF as target; a page list uses `PdfEditor::extract` (no outline/metadata), an empty list writes the working bytes as they are. Windows: untested here (code written for `MoveFileExW`/`FlushFileBuffers`).
