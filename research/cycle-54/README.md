# Cycle 54: explicit completions and opt-in Smart Quotes

Phase 54a adds the captured View → Show Completions action as an explicit local request. A later direct iA sample check found that enabling Smart Quotes changed typed straight double quotes to curly quotes, disabling it left them straight and one Undo restored the pre-substitution form. Phase 54b implements only that observed Smart Quotes subset; it does not infer the other substitution or correction behaviors.

View → Show Completions uses Unicode words in the current document. It excludes code spans/blocks, indented code and URL/link destinations. Nothing is inserted until a suggestion is accepted; acceptance rechecks the caret and unchanged prefix, then makes a single atomic replacement for Undo. IME preedit is excluded. Work is bounded to the first 50,000 UTF-16 units and 256 matching occurrences, with at most 12 choices; later words may be omitted.

`./bin/build` and the full native-access `./bin/test` suite pass with **89 tests, zero failures and zero skips**. Focused tests cover the candidate rules, stale-caret refusal, Undo and a long-document time bound. The refreshed Dev app displayed two suggestions for `lan`; Return accepted one and Command-Z restored the prefix in a disposable temporary file. [Native log](native-menu.txt). Popup visuals, arrow traversal, Escape, dark/narrow appearance, IME and accessibility remain unverified because screenshot capture was unavailable. Use only [the synthetic sample](sample/Completion.md) for further QA.

Smart Quotes is off by default and persists as a workspace preference under Edit → Substitutions. It handles only a directly typed `"`; paste and selection replacement never enter the substitution path, and active IME composition is refused. It inserts `“` after whitespace/open punctuation and `”` after prose/closing punctuation. The literal keystroke and substitution are separate undo records: the first Undo restores `"`, and the second removes it. Fenced, indented and inline code, bare URLs, Markdown link destinations and incomplete raw tags are excluded. Existing Markdown is never scanned or rewritten, and the saved file remains ordinary UTF-8.

For phase 54b, `./bin/build` and the full native-access `./bin/test` suite pass with **100 tests, zero failures and zero skips**. The focused test covers persisted menu state, opening/closing output, the two-stage Undo sequence and protected Markdown contexts. A restricted preliminary run hit existing macOS service/single-instance sandbox failures; the required native-access run passed. The [native Smart Quotes check](native-smart-quotes.txt) observed the menu, typed curly quotes, Command-Z restoring the final straight quote, disabled straight input and the discard prompt on a disposable draft. Dev returned to its prior clean Second.md sample. Both ordinary and Dev bundles were refreshed and strict signature-verified; the ordinary bundle reopened its prior saved document and exposed Substitutions → Smart Quotes.

The [24 September native iA capture](../menu-audit-2026-09-24/native-submenus.md) supplies Edit submenu labels, and the [sample-input follow-up](native-substitutions.txt) supports the bounded Smart Quotes behavior. Smart Dashes, Text Replacement, automatic correction/capitalization and other hidden behaviors remain unimplemented. Actual IME, paste, selection, non-US keyboard, recovery/restart, dark/narrow and accessibility behavior still needs native verification. Dictation/AutoFill are AppKit-provided and remain OS-dependent.
