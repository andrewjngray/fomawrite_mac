# Fomawrite product rename (Cycle 60)

The product is **Fomawrite**. The ordinary macOS bundle is `dist/Fomawrite.app` with identifier `io.github.andrewjngray.fomawrite`; the stable QA bundle is `dist/Fomawrite Dev.app` with identifier `io.github.andrewjngray.fomawrite.dev`. The executable and Linux package name are lowercase `fomawrite`. The GitHub repository is `andrewjngray/fomawrite_mac`. The physical local checkout directory was renamed to `fomawrite_mac` on 25 September 2026. Existing generated qmake files were regenerated from the new path. The old directory is not retained as a symlink because Codex rejects symlinked writable roots.

Changing the bundle ID creates a new macOS app identity. On first launch, Fomawrite copies the former Qt preferences from `io.github.andrewjngray.omawrite` into `io.github.andrewjngray.fomawrite`, with previous user choices taking priority over new defaults. Both old app bundles shared the former Qt preference domain. It copies the matching prior workspace snapshot and any recovery JSON into the new Application Support namespace, then writes a migration marker so a discarded draft is not re-imported on subsequent launches. The old state is left intact as a fallback. This is a local copy, not a cloud transfer. Avoid running old and new apps against the same document at once.

Existing hidden `.omawrite-authors.json` document sidecars and `application/x-omawrite-authorship+json` clipboard metadata remain at their established names for compatibility. This retains saved manual annotations and cross-window transfer; they are storage-format identifiers, not the product label. No user Markdown file or historical screenshot was renamed. The upstream MIT copyright and bundled font licence remain intact. Git history, previous tags and the older `Omawrite` RC1 download retain their historical names; a newly branded downloadable release has not been published.

The app names and migration were checked in both packaged bundles on macOS using clean saved sample documents. Source tests and native bundle signatures are recorded in [Cycle 60](../research/cycle-60/README.md). Changing bundle IDs may cause macOS to request app access again; only Andrew can grant it.
